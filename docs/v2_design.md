# v2.0 の設計(実装の正本)

更新: 2026-11-05(#72)。設計の元は代表と詰めた設計キャンバス(10/28〜11/4)と、11/5 の定例の決定。キャンバスと食い違うところは 11/5 の決定が正。
この文書は「v2.0 で何をどう作るか」の正本。今のコードが何をしているかは `docs/service_specification.md`(v2.0 の公開時に書き直す)。

## 1. 骨格

- **1人1アカウント**。同じアカウントで「相談する」と「支える」を切り替える。運営(ADMIN)は相談する顔を持たない
- **パスワードを持たない**。メールに届く 6 けたのコードと Google で入る
- **相談する人に聞くのは、呼び名・年齢・国と地域(市区町村まで、任意)・言語だけ**。氏名・電話・住所・性別・生年月日を持たない。市区町村は一覧から選び、全国地方公共団体コードで持つ(2026-11-27 #173。自由入力だと番地まで書けてしまうため)。相談者の市区町村と都道府県の公的な窓口を、相談の提案の 1 つに出せる
- **入口は「わたし(個人)・会社・地域」**、データは1本(`cases.subject_type`)。国の入口は v2.0 では出さない
- **相談は個人・会社・地域とも先に書き、届けるときにログインする**(2026-11-17 岡本さん)。書いた内容はログインの往復のあいだ端末に預け、戻ったら届ける段から続ける。`src/components/app/RequireMe.tsx` の `OptionalMe`・`src/lib/domain/consultDraft.ts`
- **会社・地域の相談は、先に相談を書き、届けるときに「どの団体として届けるか」を選ぶ**(所属がなければその場で登録して届ける)。団体の登録を先に求めない(2026-11-17 岡本さん「何が得られるか分からないのに登録を先にする人はいない」)。`src/components/consult/WriteFlow.tsx` の `organizationStep`
- **指標(SDGs のグローバル指標)が背骨**。相談者は困りごとを選ばず、相談を届けるときに AI が選択肢から指標を選ぶ(#133、2026-11-17 運営了承)。相談の指標は、AI が選んだもの(v2 の初めの相談は本人が選んだもの)・運営の確定を分けて持つ(`case_indicators`)
- **相談の時点の要約は作らない**(#134)。支える側は相談者の言葉をそのまま読む。AI が書くのは題だけ
- **呼び方**(#135): 相談する側は個人・会社・地域とも「相談者」、支える側の団体は「支援団体」、会社・地域として相談するための登録は「相談者の会社・地域」(`AGENTS.md`)
- **言語は ja・en・es**。書体は言語ごとに Noto を切り替える

## 4. 審査(11/5)

申し込みフォーム(簡単な情報と10項目)→ 運営へのメール → 面談(運営のチェックリスト)→ 承認(管理画面)→ 一覧に載る。2段階に分けない。公開情報との照合は必須にしない。
`organizations.vetting_status`: APPLIED → INTERVIEW → APPROVED(または REJECTED / SUSPENDED)。

**相談のための団体は審査しない**(2026-11-17 代表了承、#131)。会社・地域として相談するために登録した団体(`application.purpose = CONSULT`)は、支え手の決まりへの同意も6つの自己採点もしていないので、審査の列に並べず(`NOT_APPLIED`)、支える側の顔・招く団体・公開の一覧に出さない。相談するのに承認は要らない。運営ができるのは止める・止めるのを解くことだけで、団体として相談できないのは止めた団体だけ(見送りは支え手の申し込みを断ったという意味で、相談は止めない)。
その団体で支えるときは、管理の人が「支え手になる」の画面で今の団体を選んで申し込む(`/api/orgs/[id]/supporter-application`)。同意と6つの自己採点をすると用途が SUPPORT になって審査の列に並び、承認で「運営と面談済み」が付く。決まりは `src/lib/domain/orgVetting.ts`、DB の決まりは `v2_15`。

**掲載台帳の行と支援団体を結ぶ**(2026-11-19 定例、#140)。支援団体の申し込みでは、活動地域(全国か地域を 1 つ以上)を必ず選ぶ(前は「活動している地域」を文章で書いてもらっていた)。団体名(と任意の法人番号)を入れると、掲載台帳の民間の団体・公開中・まだ結んでいない行から、名前の鍵の部分一致か法人番号の一致で 5 つまで「この団体でしょうか」と出す(`/api/support/directory-candidates`。返すのは名前・都道府県・サイトと出典の表記だけ)。選ばれた行は申し込み(`application.directoryEntryId`)に残すだけで、**結ぶのは運営の承認のとき**(面談で本人の団体かを確かめる前に結ぶと、名の知れた団体を名乗る申し込みで行を取られるため)。承認で `claim_status = CLAIMED`・`claimed_organization_id` を付け、行の名前と活動地域(`service_scope`・`service_codes`)を申し込みの内容に合わせ、法人番号は行に無いときだけ足す。出典の列(`source_*`・`license`・`attribution`)と、出典から調べた電話・住所・相談の受け方は変えない。前の値は `audit_logs`(`admin.directory_entry_claim`)に残す。結んだ行は相談に合う支援団体の提案に出ない。取り込み(`scripts/import-directory-entries.mts`)は結んだ行の名前・法人番号・活動地域を出典の値で戻さない。運営は審査の画面で、選んだ行を外す(面談で別の団体と分かったとき)・承認のあとに結び直すことができる。選ばなかった申し込みは今までどおり新しい団体として登録する。決まりは `src/lib/domain/directoryClaim.ts`。
