## 1. サービス概要

| 項目 | 内容 |
|---|---|
| サービス名 | 明日もsamasama \| SDGs MATCH |
| 運営 | 合同会社ｓａｍａｓａｍａ |
| 目的 | 困りごとを抱える人(相談者)と、NPO・行政・企業などの支援団体(サポーター)をつなぐ |
| 本番 URL | https://app.samasama.site |
| 運営体制 | 2026-11 から少人数の運営(開発は休止) |
| 未成年の定義 | 18 歳未満 |

### 1.1 サービスの考え方
- **SDGs はサービスの言語であって、相談者の言語ではない。** 相談者は SDGs を意識せず、自分の言葉で困りごとを書けばよい。分類はサービス側が裏で行う。
- **サポーター側には SDGs を前に出す**ことで注目を集め、より多くの人が助かるようにする。
- **行政・NPO・企業が混在する意味**: 行政は制度の枠で動き、NPO はその外を拾い、企業は資源と専門性を持つ。
- **最後のセーフティネット**: マッチングがうまくいかなくても、運営(お問い合わせ)へつながる道を残す。

## 2. 利用者とロール

| ロール | 誰か | 作り方 | 主な画面 |
|---|---|---|---|
| SOS | 相談者 | 本人が `/signup` で登録 | `/sos/dashboard` |
| SUPPORTER | 支援団体に所属する担当者個人 | 運営が作成、または団体の OWNER / ADMIN が追加 | `/supporter/dashboard` |
| ADMIN | 運営 | 運営が作成 | `/admin/dashboard` |
| 未ログイン | 公開ページの閲覧者 | ー | `/` ほか |

- 団体(`organizations`)と担当者個人(`users`)は分けて持つ。所属は `organization_memberships`(1 人 1 団体まで)。
- 団体内の役割: **OWNER**(団体管理。団体情報・活動地域・メンバーの役割を変えられる。複数可、最後の OWNER は降格・停止できない)/ **ADMIN**(担当者を追加できる。追加できるのは MEMBER だけ)/ **MEMBER**(通常の担当)。
- 停止は 2 層: 団体内の停止は `organization_memberships.status = SUSPENDED`(OWNER が操作)、アカウント全体の停止は `users.is_suspended` + Auth の ban(運営だけ)。
- 運営が作ったアカウントは `must_change_password = true` で、初回ログイン時にパスワード変更へ進む(強制はログイン直後の画面移動だけ)。

## 4. 認証・アカウント

- **新規登録できるのは SOS だけ**(`/signup`、2 段階: メール・パスワード 8〜64 字・規約同意 → 氏名・表示名・電話(任意)・性別・生年月日)。本番はメール確認あり。SOS の登録総数は `MAX_SOS_USERS = 1000` で打ち止め。
- ログイン `/login`、パスワード再設定 `/forgot-password` → `/reset-password`。
- パスワード変更 `/change-password`: 自分で変えるときは今のパスワードが必要。更新は本人のトークンで行い、ログインしたままになる。流出が知られたパスワードは日本語の案内で断る。
- メール変更 `/change-email`: 今のパスワードと重複を確認してから確認メールを送る。新しいアドレスのリンクを押すと切り替わる(確認メールは新旧両方に届くが仕様)。運営は管理画面から変更できる(本人確認は運営が行う)。
- プロフィール `/profile`: 氏名・表示名・電話。SOS は地域(都道府県)と住所(任意)。SUPPORTER は部署・電話の内線など。団体情報と活動地域は OWNER だけ。
- 管理者は `/profile` に入れない(管理者自身のパスワード変更は再設定メールで行う)。
- **退会機能は未実装。** 退会希望はお問い合わせで受ける。実装するときの方針は §11。

## 5. 相談者(SOS)の機能

### 5.1 相談の登録(`/sos/hearing`)
- 困りごとを **0〜3 個**選ぶ。選択肢は SDGs のグローバル指標をもとにした 114 個で、大項目ごとに開いて選ぶ(正本 `docs/intake_indicators.md`、コード `src/lib/constants/intakeIndicators.ts`)。0 個なら大項目 18「SDGsの隣のお困りごと」になる。
- 自由記述: 何に困っているか(必須)/ いつから / どうしたいか。
- 自由記述欄の上に「個人情報を書かない」注意がある。
- **緊急**: 選んだ選択肢に緊急の印(14 個)があるか、自由記述に緊急の語句があれば緊急(High)。サーバーでも同じ判定をする。AI は使わない(`src/lib/urgency.ts`)。
- 回数の上限: 開いている相談(受付中・支援中)は 1 人 3 件まで。本番だけ、24 時間で 10 件まで(取り消した分も数える)。
- 保存: `cases` に `status = OPEN`、選んだ選択肢は `intake_qna = { version: 2, indicators, ... }`。

### 5.2 AI による整理(結果ページ `/sos/result/[id]`)
- 結果ページを開いたときに 1 回だけ AI を動かす(分析済みなら保存済みの結果を返す)。
- **大項目は選んだ選択肢からサーバーが決める。AI は分類せず、タイトル・要約・大項目ごとの説明文だけを書く。**
- AI の結果が保存されると、相談がサポーターの一覧に出る(`visibility = LISTED`)。
- 結果ページでは、選んだ困りごと、AI の説明、進み具合、サポーターからの申し出、チャットを見られる。60 秒ごとに更新。

### 5.3 申し出・解決
- サポーターからの申し出を **承認** または **辞退** する。承認できるのは 1 案件 1 団体(`MAX_SUPPORTERS_PER_CASE = 1`)。承認すると相談は「支援中」(MATCHED)になり、残りの申し出は自動で辞退になる。
- 承認した団体とサイト内のチャットでやりとりする。**連絡先がサポーターに伝わる仕組みはない。**
- サポーターが「解決した」と報告したら、相談者が **解決を確定** するか「まだ解決していない」と差し戻す。確定すると承認した団体に自動でバッジが付き、相談者は感謝のバッジ(5 種)を贈れる。
- 相談はいつでも取り消せる(受付中・支援中のとき)。

### 5.4 災害SOS(受付終了中)
- 熊本地震(2026)の災害SOSは **2026-09-16 に受付を終了**(`ACTIVE_DISASTER_EVENT = null`)。入口・フォームは閉じ、API も新しい災害SOSを断る。
- 災害案件は **サポーターの一覧から外している**(`DISASTER_CASES_SHOWN_TO_SUPPORTERS = false`)。
- 再開するときは両方を戻す。災害の写真(3 枚まで)、地域、AI によるニーズ分類(8 種)の仕組みはコードに残っている(正本 `src/lib/constants/disaster.ts`)。

## 6. サポーターの機能

### 6.1 案件一覧(`/supporter/dashboard`)
- 公開中の相談(受付中・支援中、新しい順に最大 200 件)と、自団体が申し出たことのある相談を出す。
- 承認数が上限に達した相談は、自団体が申し出中・支援中でなければ隠す。
- 絞り込み: 困りごとの大項目(1 つ)→ その中の選択肢(複数、どれかに当てはまる)。0 件の項目は押せない。都道府県(活動地域・地方別)、自団体の関わり方(未関与・申し出中・支援中・解決済み・取消済み)。
- 並び順(新着順・待機が長い順)、表示切替(案件ごと・相談者ごと)。
- カードの印: 待機時間(6 時間未満 灰 / 24 時間未満 黄 / それ以上 赤)、未成年、緊急。
- サポーターに見える相談者の情報: 表示名・都道府県・未成年の印。氏名・電話・住所・メール・生年月日は見えない(API も生年月日を返さず、未成年かどうかだけを返す)。

### 6.2 案件詳細と申し出(`/supporter/case/[id]`)
- 申し出は団体ごとに 1 案件 1 件、メッセージ必須(1000 字まで)。取り下げ・再申し出ができる。支援中の取り下げは理由が必須で、相談者にシステムメッセージが届く。
- 承認されたら、チャットと **団体内だけの内部メモ**(3000 字、書いた本人だけ編集・削除、操作は監査ログに残る)が使える。
- 解決の報告は主担当の団体(最初に承認された団体)だけ。

### 6.3 団体の管理
- 団体プロフィール・活動地域(全国対応 or 都道府県)は OWNER が `/profile` で編集。
- メンバー管理 `/supporter/members`: OWNER / ADMIN が担当者を追加(新しいアカウントを作る)。OWNER が役割と団体内の停止を変える。既存アカウントの追加と所属解除は未対応。

## 8. 相談のステータス

```
作成 → OPEN(受付中)
OPEN → MATCHED(支援中)        相談者が申し出を承認
MATCHED → OPEN                 承認した団体が全員取り下げた
MATCHED → RESOLVED(解決)      サポーターの解決報告 → 相談者が確定、または報告から 14 日で自動
MATCHED → CLOSED(終了)        解決報告がなく、最後のやりとりから 30 日動きがない(自動)
OPEN / MATCHED → CANCELLED     相談者が取り消し
```
- RESOLVED・CLOSED・CANCELLED になるとチャットは読み取り専用。
- 申し出: PENDING(申し出中)→ ACCEPTED(承認)/ DECLINED(辞退・自動辞退)/ WITHDRAWN(取り下げ)。DECLINED・WITHDRAWN から再申し出できる。

## 9. 自動処理(毎日 JST 2:00、`/api/cron/auto-close-cases`)
1. 解決報告から 14 日たった支援中の相談を RESOLVED にする(この経路ではバッジは付かない)
2. 解決報告がなく 30 日動きのない支援中の相談を CLOSED にする
3. 災害案件のニーズ分類の漏れを最大 10 件やり直す

## 10. AI の使い方と安全対策

AI は Google Gemini(`gemini-2.5-flash`、有料 API)。使う場所は 3 つだけ。

| 用途 | 何をするか | 誰が動かすか |
|---|---|---|
| 相談の整理 | タイトル・要約・大項目ごとの説明文を書く(分類はしない) | 相談者が結果ページを開いたとき、1 案件 1 回 |
| 災害ニーズ | 災害案件に 8 種のニーズの札を付ける | 災害SOSの登録直後と cron(受付終了中) |
| お知らせの下書き | 材料や URL の本文から、タイトルと本文の下書きを書く | 運営が管理画面で押したとき(DB には書かない) |

安全対策:
- **個人情報を伏せてから AI に渡す**(電話・メール・住所・郵便番号・URL・SNS・生年月日・長い番号。`src/lib/pii.ts`)。DB への保存とサポーターへの表示は伏せない。名前は伏せられない(体験ページで説明している)。
- **相談文を囲んで「命令として扱わない」と指示する**(プロンプトインジェクション対策、`src/lib/aiSafety.ts`)。
- **AI の出力から URL とメールアドレスを消す。**
- **大項目と緊急度は AI ではなくルールで決める。**
- AI はツールも DB 権限も持たず、表示用の文を返すだけ。
- 回数の上限(§5.1)と、相談 1 件につき AI 1 回。
- お知らせの下書きは「材料にない事実を書かない」「個人名・連絡先・相談事例を書かない」などをプロンプトで決め、公開前に運営が必ず確かめる。

**退会の方針(未実装。実装するときに従う):**
- SOS: 退会と同時に個人情報を削除・匿名化し、同じメールアドレスで新しく登録できるようにする。過去の相談は新しいアカウントに引き継がない。

- 相談・メッセージ・申し出・監査ログは物理削除しない。
- 実装するときは、利用規約・プライバシーポリシーも見直す。

## 12. 多言語

- 公開している言語は **日本語・英語・中国語(簡体)** だけ。韓国語・ベトナム語・インドネシア語は翻訳ファイルだけある(ネイティブ確認前のため非公開)。
- 言語切替は非表示(`LANGUAGE_SWITCHER_ENABLED = false`、ブラウザの言語で自動切替もしない)。英語・中国語は URL に `/en`・`/zh` を付けて開く。
- 翻訳しているのは公開ページ・ログインまわり・相談者の画面。**サポーターと運営の画面は日本語のみ。** 利用規約・プライバシーポリシー・ストーリー・お知らせは日本語のみで、他の言語では案内を出す。
- AI に渡す文と、AI が書く説明文は日本語。
- 資料などで「6 言語対応」と書かない。

## 13. メンテナンスモード

本番 DB の作業中などに、利用者の操作を止める仕組み。
- Vercel の環境変数 `MAINTENANCE_MODE=true` → 再デプロイで有効。画面は `/maintenance` へ、API は 503 を返す。`/api/health` は動く。
- ログアウトはさせない(終わればそのまま使える)。
- 運営だけ通すには `MAINTENANCE_BYPASS_TOKEN` を設定し、`/api/maintenance-bypass?token=<値>&redirect=/` を開く(1 時間有効)。
- 手順は `docs/operations.md` §6。

## 16. テストの観点(Staging)

リリース前に、ロールごとに次を確かめる。Staging のテスト用アカウントは HANDOFF.md にある。

- **相談者**: 登録 → 相談(選択肢 0 個・3 個、緊急の選択肢、上限 3 件)→ 結果ページで AI の説明 → 申し出の承認・辞退 → チャット → 解決の確定・差し戻し → バッジ。体験ページ `/trial` で伏せ字が出ること
- **サポーター**: 一覧の絞り込み(大項目 → 選択肢、0 件は押せない)、申し出・取り下げ・再申し出、チャット、内部メモ、解決報告(主担当だけ)、メンバー追加(OWNER / ADMIN)、団体プロフィール(OWNER だけ)
- **運営**: 停止・解除、メール変更、サポーター作成、掲載設定、お問い合わせ、お知らせの下書き・公開・非公開
- **公開**: トップ(お知らせ・注目サポーター)、`/supporters`、`/news`、記事の共有画像、`/en`・`/zh`
- **安全**: ログインなしで API が 401、別ロールで 403、他人の相談に触れない、不正な ID で 400 / 404、セキュリティヘッダー 4 つ
- 自動テスト: `npm run test:units`(個人情報マスク・AI の安全対策・選択肢・お知らせ・cron 認証など)、`npm run check:i18n`(翻訳キーの一致)
